# Product Namer

AI-агент, который подбирает названия для продукта. Пользователь вводит URL статьи или страницы с описанием продукта. Агент загружает HTML, извлекает основной текст, с помощью модели OpenAI составляет профиль продукта и возвращает **5 уникальных названий** с краткими пояснениями.

> Названия генерируются автоматически. Сервис не проверяет товарные знаки и доступность доменов, поэтому перед использованием названия проверяйте отдельно.

## Как это работает

1. **Проверка URL.** Допускаются только `http(s)`, публичный домен и порты 80/443/8080/8443. Домен разрешается через DNS, и **все** полученные IP-адреса должны быть публичными.
2. **Загрузка страницы** через `requests`: ограничены тайм-аут и размер, редиректы обрабатываются вручную, каждый из них проходит ту же проверку. Временные ошибки (сеть, тайм-аут, HTTP 429/5xx) повторяются через `tenacity`.
3. **Извлечение текста** через BeautifulSoup. Удаляются `script`, `style`, `noscript`, `svg`, `iframe`, навигация, реклама, футеры, cookie-баннеры и скрытые элементы. Берутся заголовок, метаописание и основной блок (`<article>` → `<main>` → `<body>`). JavaScript не выполняется. Текст обрезается до `MAX_TEXT_LENGTH`.
4. **Анализ продукта.** Модель составляет структурированный профиль: назначение, аудиторию, преимущества, характеристики, стиль бренда. Факты, которых нет в источнике, не допускаются.
5. **Генерация названий** по профилю и исходному тексту с использованием Structured Outputs (JSON Schema, `strict`).
6. **Проверка результата.** JSON проверяется по схеме Pydantic. Названия нормализуются (пробелы, кавычки). Дубликаты определяются без учёта регистра, пробелов и пунктуации и отбрасываются вместе с пустыми и слишком длинными вариантами, а также с текущим названием продукта. Если валидных вариантов меньше 5, генерация повторяется один раз. Если и после этого их меньше 5, API возвращает ошибку 502.

Каждый запрос — это 2 вызова модели (анализ и генерация), при повторной генерации — 3.

## Архитектура

```text
product_namer/
├── app/
│   ├── main.py            # FastAPI: маршруты, обработчики ошибок, веб-интерфейс
│   ├── agent.py           # Сценарий агента, промпты, проверка и дедупликация названий
│   ├── openai_module.py   # Вызовы OpenAI: Structured Outputs, повторы, маппинг ошибок
│   ├── scraper.py         # Безопасная загрузка (SSRF), извлечение текста из HTML
│   ├── schemas.py         # Pydantic-модели запросов, ответов и данных агента
│   ├── config.py          # Загрузка и проверка .env, настройка логирования
│   ├── errors.py          # Исключения с пользовательским сообщением и HTTP-статусом
│   ├── utils.py           # Повторы (tenacity), маскирование URL для логов
│   └── templates/index.html
├── tests/                 # pytest: scraper, agent/OpenAI, API (всё на моках)
├── logs/                  # Логи при локальном запуске
├── Dockerfile
├── docker-compose.yml
├── requirements.txt       # Зависимости приложения
└── requirements-dev.txt   # + pytest, httpx
```

Модули `config.py`, `errors.py` и `utils.py` добавлены к исходной структуре. В них вынесены общие для нескольких модулей настройки, исключения и логика повторов, чтобы её не дублировать.

## Требования

- **Docker** 24+ с Docker Compose v2 — для запуска в контейнере;
- или **Python 3.10+** — для локального запуска (проверено на Python 3.13 и в образе `python:3.12-slim`);
- API-ключ OpenAI с доступом к выбранной модели (по умолчанию `gpt-4.1-mini`).

## Получение API-ключа OpenAI

1. Войдите на <https://platform.openai.com/>.
2. Откройте **API keys** (<https://platform.openai.com/api-keys>) и нажмите **Create new secret key**.
3. Скопируйте ключ: он показывается один раз.
4. Убедитесь, что в разделе **Billing** есть средства или лимит. Без них API вернёт `insufficient_quota`.
5. Проверьте, что выбранная модель есть в разделе **Limits** вашего проекта.

## Настройка .env

```bash
cp .env.example .env      # Windows PowerShell: Copy-Item .env.example .env
```

Откройте `.env` и укажите реальный `OPENAI_API_KEY`. Остальные параметры:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `OPENAI_API_KEY` | — | **Обязательно.** Ключ OpenAI API |
| `OPENAI_MODEL` | `gpt-4.1-mini` | Модель. Меняется без правки кода |
| `REQUEST_TIMEOUT` | `15` | Тайм-аут загрузки страницы, сек |
| `OPENAI_TIMEOUT` | `60` | Тайм-аут запроса к OpenAI, сек |
| `MAX_RETRIES` | `3` | Общее число попыток при временных ошибках, включая первую |
| `MAX_PAGE_SIZE` | `2000000` | Максимальный размер страницы, байт |
| `MAX_TEXT_LENGTH` | `20000` | Максимальная длина текста для модели, символов |
| `LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `LOG_FILE` | `logs/app.log` | Файл логов (в Docker всегда `/app/logs/app.log`) |
| `MAX_REDIRECTS` | `5` | Максимум перенаправлений |
| `VERIFY_MODEL_ON_STARTUP` | `true` | Проверять при старте ключ и доступность модели |

Конфигурация проверяется при запуске. Если ключ не задан, числа некорректны, ключ отклонён или модель недоступна, приложение не стартует и пишет в лог понятную причину. Если OpenAI при старте недоступен из-за сетевой ошибки, приложение всё равно запускается и пишет предупреждение.

`.env` не попадает в Git (`.gitignore`) и в Docker-образ (`.dockerignore`).

## Запуск через Docker

```bash
cp .env.example .env            # затем впишите OPENAI_API_KEY
docker compose up --build -d
```

Откройте <http://localhost:8000>.

```bash
docker compose ps                     # статус и healthcheck (healthy)
docker compose logs -f                # логи приложения в реальном времени
docker compose restart                # перезапуск (например, после правки .env)
docker compose down                   # остановить и удалить контейнер (логи в volume сохранятся)
docker compose down -v                # то же + удалить volume с логами
```

Как настроен контейнер:
- образ `python:3.12-slim`, приложение работает от пользователя `app` (uid 10001);
- корневая ФС только для чтения, `no-new-privileges`;
- секреты передаются только через `env_file: .env`;
- `restart: unless-stopped`, healthcheck через `GET /health`;
- логи пишутся в именованный volume `product_namer_logs` (`/app/logs`);
- uvicorn запускается без `--reload` (не в режиме разработки).

## Локальный запуск без Docker

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
.venv\Scripts\Activate.ps1

pip install -r requirements-dev.txt
cp .env.example .env            # впишите OPENAI_API_KEY
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Для разработки можно добавить `--reload`. Swagger UI доступен по адресу <http://localhost:8000/docs>.

## Веб-интерфейс

1. Откройте <http://localhost:8000>.
2. Вставьте URL страницы с описанием продукта и нажмите **«Подобрать названия»**.
3. Пока идёт обработка (обычно 10–30 секунд), кнопка заблокирована и показан индикатор загрузки.
4. Результат — 5 карточек с названием и пояснением. У каждой карточки есть кнопка **«Копировать»**, а кнопка **«Копировать все»** копирует список целиком.
5. При ошибке отображается понятное сообщение.

## REST API

### `POST /api/generate`

```bash
curl -X POST http://localhost:8000/api/generate \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com/product"}'
```

Windows PowerShell:

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/generate `
  -ContentType "application/json" -Body '{"url": "https://example.com/product"}'
```

Успешный ответ (`200`):

```json
{
  "source_url": "https://example.com/product",
  "names": [
    {"name": "Nova", "reason": "Короткое название, передающее ощущение новизны."},
    {"name": "Lumio", "reason": "Ассоциируется со светом и понятностью."},
    {"name": "Vektor", "reason": "Подчёркивает направленность и эффективность."},
    {"name": "Forma", "reason": "Звучит лаконично и подходит современному продукту."},
    {"name": "Orbito", "reason": "Передаёт идею целостности и технологичности."}
  ]
}
```

Ошибки возвращаются в формате `{"detail": "<сообщение>", "error_type": "<код>"}`:

| Статус | Когда | `error_type` |
|---|---|---|
| `422` | Некорректный URL или тело запроса; внутренний адрес; на странице мало текста | `validation_error`, `invalid_url`, `blocked_url`, `insufficient_content` |
| `502` | Сайт вернул ошибку или недоступен; ошибка OpenAI; некорректный ответ модели | `fetch_failed`, `llm_error`, `llm_invalid_response` |
| `504` | Тайм-аут сайта или OpenAI | `fetch_timeout`, `llm_timeout` |
| `500` | Непредвиденная внутренняя ошибка | `internal_error` |

### `GET /health`

```json
{"status": "ok", "version": "1.0.0", "model": "gpt-4.1-mini"}
```

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тесты не требуют API-ключа и интернета: HTTP-запросы, DNS и OpenAI SDK заменены моками. Они покрывают:
- извлечение текста и удаление шума;
- пустые страницы;
- некорректные URL;
- блокировку localhost, приватных и служебных IP, в том числе через редирект, DNS и на уровне сокета;
- лимиты размера и редиректов;
- сетевые ошибки и тайм-ауты;
- повторы и лимит попыток;
- отсутствие повторов при постоянных ошибках (401, 404, `insufficient_quota`);
- переход на JSON mode;
- проверку схемы и удаление дубликатов;
- повторную генерацию;
- эндпоинты `/api/generate`, `/health` и `/`;
- проверку конфигурации.

## Логи

В каждой строке есть время, уровень, этап (`stage=fetch|extract|analyze|generate|validate|request`), событие, URL без query-параметров и учётных данных, тип ошибки, число попыток и длительность:

```text
2026-10-14 21:17:42,351 INFO app.scraper stage=fetch event=downloaded url=https://en.wikipedia.org/wiki/Espresso_machine?<redacted> bytes=222080 attempts=1
2026-10-14 21:17:43,715 WARNING app.agent stage=analyze event=failed url=https://... error_type=llm_error attempts=1 duration_ms=1239 cause=AuthenticationError
```

API-ключи, тексты страниц и промпты в лог не пишутся. Файл ротируется при 5 МБ, хранится 5 архивов.

- Docker: `docker compose logs -f` или `docker compose exec product-namer tail -f /app/logs/app.log`
- Локально: файл `logs/app.log`

## Безопасность

- **SSRF.** URL проверяется до запроса и при каждом редиректе. Дополнительно используется собственный `HTTPAdapter`: он заново разрешает DNS при открытии сокета и подключается только к проверенному публичному IP. Это защищает от DNS rebinding. Сертификат HTTPS проверяется по исходному домену. Блокируются loopback, частные сети, link-local (в том числе `169.254.169.254`), CGNAT (`100.100.100.200`), IPv6 ULA/loopback, IPv4-mapped IPv6, а также имена `localhost`, `*.internal`, `*.local`, `metadata.google.internal`. Переменные прокси игнорируются.
- **Prompt injection.** Текст страницы передаётся модели только в пользовательском сообщении внутри разделителей `<source_document>`. Попытки закрыть разделитель внутри текста вырезаются. Системный промпт запрещает выполнять инструкции из этих данных.
- **XSS.** Интерфейс выводит ответ модели только через `textContent`.
- **Секреты** хранятся только в `.env`, который исключён из Git и Docker-образа. `repr(Settings)` не показывает ключ.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| Контейнер в статусе `restarting`, в логах `Не задан OPENAI_API_KEY` | В `.env` остался шаблонный ключ. Укажите реальный и выполните `docker compose up -d` |
| `Ошибка авторизации в OpenAI API` | Ключ неверный или отозван. Создайте новый ключ |
| `Модель ... не найдена или недоступна` | У проекта нет доступа к модели из `OPENAI_MODEL`. Выберите доступную модель |
| `Исчерпана квота OpenAI API` | Пополните баланс в разделе Billing |
| `На странице недостаточно текста` | Страница рендерится через JavaScript (SPA) или требует авторизации. Используйте другую страницу (статью, пресс-релиз) |
| `Этот адрес недоступен для загрузки` | URL ведёт на localhost или во внутреннюю сеть, это запрещено намеренно |
| `Сайт вернул ошибку HTTP 403` | Сайт блокирует ботов. Попробуйте другую страницу |
| `Страница слишком большая` | Увеличьте `MAX_PAGE_SIZE` |
| `port is already allocated` | Порт 8000 занят. Поменяйте левую часть в `ports:` (например, `"8080:8000"`) |
| Ошибка 504 | Сайт или OpenAI отвечают медленно. Увеличьте `REQUEST_TIMEOUT` / `OPENAI_TIMEOUT` |
| Модель не поддерживает Structured Outputs | Приложение само переходит на JSON mode, а ответ всё равно проверяется по схеме |
